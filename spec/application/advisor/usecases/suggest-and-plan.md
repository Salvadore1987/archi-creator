# UC-ADV-002 — Подсказка по элементу и план модели по описанию

**Актор:** `ARCHITECT` · **Результат:** объяснение и `ModelPlan` — описание,
а не изменение модели

Два сценария в одном файле: у них общий контур (контекст → запрос → разбор
ответа) и общая граница — ни один не пишет в модель (FR-22, `INV-ADV-004`).

## Сценарий A: контекстная подсказка (FR-24)

**Given** выбранный на канве элемент `ApplicationComponent`

**When** актор просит подсказку

**Then**
1. Контекст — сам элемент, его связи и ближайшее окружение; полная модель
   не отправляется (`INV-ADV-007`).
2. Ответ содержит объяснение типа, список допустимых связей отсюда
   (по матрице ArchiMate, а не по догадке модели) и предложение следующего шага.
3. Список допустимых связей берётся из `RelationMatrix` детерминированно —
   помощник его формулирует, но не вычисляет: иначе в подсказке появятся
   связи, которые сервер отклонит (`INV-MDL-007`).

## Сценарий B: план модели по описанию (FR-25)

**Given** текстовое описание фрагмента архитектуры

**When** актор запрашивает генерацию

**Then**
1. Возвращается `ModelPlan`: список `PlannedElement` (имя, тип) и
   `PlannedRelation` (тип, концы по позиции в плане).
2. План **не применяется**: в модели ничего не создаётся, ни одной команды
   записи не выполняется (`INV-ADV-004`).
3. Палитра на канве фильтруется по предложенным типам, чтобы архитектор собрал
   схему быстро — это подсказка интерфейса, а не изменение модели.
4. Типы, отсутствующие в фазе 1, в план не попадают.

## Сценарий C: генерация документации (FR-26)

Описание представления, каталог элементов и анализ влияния («что затронуто
при отказе компонента») с выгрузкой в Markdown. Результат — текст, ссылки
на элементы сохраняются (`INV-ADV-008`).

## Альтернативы и отказы

| Ситуация | Ответ | Поведение |
|---|---|---|
| План содержит недопустимую по матрице связь | связь помечается | Помечается как требующая внимания, но план отдаётся: это предложение, а не команда |
| Модель большая, контекст не влезает | усечение с пометкой | Пометка видна в ответе (`INV-ADV-007`) |
| Остальные отказы (бюджет, частота, выключен, недоступен) | — | Как в [`UC-ADV-001`](review-model.md) |

## Порты

**Входящие:** `ExplainElement(elementId)` → `AdvisorAnswer`,
`PlanModel(description)` → `ModelPlan`,
`GenerateDocumentation(target, format = MARKDOWN)` → `AdvisorAnswer`

**Исходящие:** `ModelContextReader`, `RelationMatrix`, `LlmPort`,
`TokenBudgetPort`, `AuditWriter`
