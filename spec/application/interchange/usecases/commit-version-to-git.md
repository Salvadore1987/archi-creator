# UC-IXC-003 — Коммит версии модели в Git

**Актор:** `ARCHITECT` (косвенно — сохранение модели) ·
**Триггер:** зафиксирована новая версия модели ·
**Результат:** коммит в ветке привязки рабочего пространства

Git здесь — журнал и предмет ревью, не способ хранения: источник правды остаётся
в PostgreSQL. Из этого следует направление обмена и запрет на переписывание
истории.

## Предусловия

- У рабочего пространства настроена и доступна привязка `GitBinding`
  в состоянии, допускающем запись.
- Версия модели зафиксирована (`UC-MDL-004`) — коммитится версия, а не текущее
  состояние редактора (`INV-IXC-008`).

## Основной сценарий

**Given** рабочее пространство с рабочей привязкой к репозиторию и новая версия
модели с комментарием автора

**When** система публикует версию в Git

**Then**
1. Модель раскладывается в YAML: `model.yaml`, `folders.yaml`, файл на элемент,
   на связь, на представление; имя файла — `<слаг>.<8 hex от id>.yaml`
   (`INV-IXC-011`).
2. Принадлежность папке пишется полем `folder`, порядок — разреженным `position`
   с шагом 1000; неподдержанное уходит в `raw_xml` блочным скаляром.
3. Писатель детерминирован: фиксированный порядок ключей, сортировка свойств,
   LF, без якорей и переносов. Повторная публикация без изменений модели diff
   не даёт (FR-40).
4. Коммит добавляется в ветку: автор — архитектор, сообщение — комментарий
   к сохранению. Только fast-forward, без force push и rebase (`INV-IXC-009`).
5. `git_sha` записывается в версию модели — по нему потом восстанавливается
   очищенный снимок (FR-46).
6. Публикуется `GitSnapshotCommitted`.

## Альтернативы и отказы

| Ситуация | Ответ | Поведение |
|---|---|---|
| HEAD ветки сдвинулся | расхождение | Экспорт помечается как расхождение и **не** перезаписывает чужой коммит (FR-37); разрешается слиянием по сущностям (`INV-IXC-010`, этап 7c) |
| Репозиторий недоступен | отложено | Версия остаётся в базе, публикация повторяется; очистка снимков при этом выключена (FR-47) |
| Привязки нет | пропуск | Сохранение модели проходит полностью, Git не участвует, снимки не удаляются никогда |
| Модель физически уничтожена (`PURGED`) | коммиты не трогаются | Репозиторий остаётся журналом (`INV-IXC-009`) |

## Порты

**Входящий:** `PushModelToGit(workspaceId, modelId, versionNo)` → `GitSha`

**Исходящие:**
- `GitYamlWriter` — детерминированная раскладка модели по файлам
- `GitRepositoryPort` — clone/fetch/commit/push, только fast-forward
- `SecretResolver` — учётные данные по `SecretRef`, в базе не хранятся
- `ModelVersionUpdater` — запись `git_sha` в версию (команда в `modeling`)

## События

`GitSnapshotCommitted` — [`../../../domain/interchange/events.yaml`](../../../domain/interchange/events.yaml).
Фиксация самой версии — `ModelVersionCommitted` из `modeling`.

## Открытое решение

Публикация событий в `interchange` сегодня `direct` — доставка в процессе после
коммита транзакции, с окном потери. Для этого сценария окно недопустимо: версия
без коммита ломает правило очистки снимков. Требуется `transactional_outbox` —
`ADR-0003`, статус `proposed`.
