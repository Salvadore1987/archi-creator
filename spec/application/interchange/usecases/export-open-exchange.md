# UC-IXC-005 — Экспорт модели в Open Exchange Format

**Актор:** `VIEWER` и выше · **Триггер:** запрос выгрузки модели с `fmt=oef` ·
**Результат:** zip из файла The Open Group ArchiMate Model Exchange File Format,
проверенного по официальной XSD, и отчёта о потерях

Односторонняя выгрузка для инструментов кроме Archi, для регулятора и подрядчиков.
Формат обмена, а не хранения: обещание lossless относится только к `.archimate`
(FR-02), поэтому каждая выгрузка несёт отчёт о том, что не перенеслось (FR-44).
Импорта из OEF нет (`ADR-0008`).

## Предусловия

- Модель существует и не удалена; актор видит её (список доступа, FR-29).
- Указана версия либо берётся последняя зафиксированная (`INV-IXC-008`).

## Основной сценарий

**Given** сохранённая модель

**When** актор запрашивает экспорт с `fmt=oef`

**Then**
1. `ExportJob` фиксирует `sourceVersionNo`; файл строится из снимка этой версии,
   правки после сохранения в него не попадают (`INV-IXC-008`).
2. Писатель переводит модель по таблице соответствий
   ([`docs/backend.md` §3.5](../../../../docs/backend.md#35-экспорт-в-open-exchange-format)):
   элементы и связи — в `elements` и `relationships` с типами OEF, дерево папок —
   в `organizations`, ключи свойств — в общий словарь `propertyDefinitions`,
   представления — в `views/diagrams` с абсолютной геометрией. Тексты пишутся
   с `xml:lang="ru"`.
3. Переносится всё, что OEF умеет выразить, независимо от фазы метамодели: тип,
   неподдержанный в редакторе (`Location`, `Grouping`, фаза 3), в OEF есть и
   выгружается. Идентификаторы — буквально.
4. Не переносится то, чего в OEF нет, и каждое такое место — запись отчёта
   (`INV-IXC-006`): остаток `raw_xml` (фрагменты, которых не знает читатель),
   представления не-ArchiMate и объекты представлений без аналога, атрибуты
   без аналога (часть стиля, маршрутизатор связей), тип корневой папки, свойства
   папок. Отчёт полон по построению: у каждого вида объекта закрытый список
   переносимых атрибутов, всё прочее попадает в отчёт.
5. Идентификатор, не годный для `xs:ID`, заменяется на производный `id-<hex>`;
   представление с отрицательными координатами сдвигается целиком — обе правки
   записываются в отчёт.
6. Результат проверяется по официальной XSD **до отдачи**.
7. Ответ — zip из `<модель>-v<N>.xml` и `loss-report.json`; число записей отчёта —
   в заголовке ответа. Повтор по той же версии даёт побайтово тот же архив.
8. Результат отдаётся как `Artifact`, публикуется `ExportCompleted`.

## Альтернативы и отказы

| Ситуация | Ответ | Поведение |
|---|---|---|
| Результат не прошёл XSD | `500` | `IXC_OEF_SCHEMA_VIOLATION`: файл не отдаётся, выгрузка — `FAILED`, текст нарушения — в журнал сервера (FR-43) |
| Модель удалена | `409` | `MODEL_DELETED` |
| Снимок версии очищен, Git не настроен | `410` | Как у `UC-IXC-002` (FR-47) |

## Порты

**Входящий:** `ExportOpenExchange(modelId, versionNo?)` → `Artifact` (zip)

**Исходящие:**
- `VersionSnapshotReader` — снимок версии

Схема и писатель — чистая Java в application-слое: XSD лежит в ресурсах модуля,
проверка идёт средствами JDK без обращения в сеть.
