# Product spec: Advisor

## Зачем существует

`advisor` — встроенный советник по нотации. Он объясняет ArchiMate, находит
в модели то, что архитектор не заметил, предлагает план будущей схемы и
пишет документацию по существующей.

Ценность — в том, что знание нотации перестаёт быть входным барьером.
Архитектор, который помнит не все одиннадцать типов связей, получает ответ
в том же окне, где рисует, а не в PDF стандарта. Ровно поэтому помощник —
второй по значимости аргумент внедрения после round-trip: Archi умеет
хранить модель, но не умеет о ней рассуждать.

**Помощник не изменяет модель.** Любой его результат — текст, ссылки на
элементы и предложения; правки вносит только архитектор (FR-22). Это не
ограничение первой версии, а граница продукта: ответственность за модель
остаётся на человеке, а доверие к инструменту не зависит от того,
насколько хороша была очередная генерация.

## In scope

- Ревью модели: нарушения матрицы связей, элементы-сироты, дубли по смыслу,
  пропущенные связи между слоями, несогласованные имена. Каждая находка
  ссылается на элемент и содержит описание исправления (FR-23).
- Контекстная подсказка по выбранному элементу: объяснение типа, список
  допустимых связей отсюда, предложение следующего шага (FR-24).
- План модели по текстовому описанию: структурированный список элементов и
  связей, по которому архитектор собирает схему сам (FR-25).
- Генерация документации: описание представления, каталог элементов,
  анализ влияния, выгрузка в Markdown (FR-26).
- Потоковая отдача ответа (SSE), первые токены ≤ 3 с (NFR-04).
- Аудит каждого обращения и бюджет токенов рабочего пространства с
  предупреждением на 80 % и остановкой на 100 % (FR-27, FR-51…FR-53).

## Out of scope

- **Изменение модели.** Ни прямое, ни через «применить предложение одной
  кнопкой». `ModelPlan` — описание, а не команда (FR-22).
- Валидация по метамодели как таковая: матрица связей и правила вложенности
  живут в `modeling` и работают без ИИ. `advisor` объясняет нарушения и
  ищет то, что формальными правилами не ловится, — дубли по смыслу,
  несогласованные имена.
- Хранение модели и доступ к файлам: `advisor` получает `ModelContext`
  через порт и не ходит в хранилище.
- Выбор и обучение моделей ИИ, промпт-инжиниринг как продукт: используется
  внешний API (`claude-sonnet-5`).

## Метрики успеха

| KPI | Целевое значение | Источник |
|---|---|---|
| Время до первых токенов | p95 ≤ 3 с (NFR-04) | `advisor_first_token_seconds` |
| Доля сессий, завершившихся ошибкой | ≤ 2 % за месяц | `advisor_sessions_total{outcome="FAILED"}` |
| Расход бюджета токенов | Ни одно рабочее пространство не достигает 100 % раньше 25-го числа месяца | `advisor_tokens_consumed{workspace}` против `ai_monthly_token_limit` |
| Полезность ревью | ≥ 30 % находок приводят к правке модели в течение недели | Сопоставление `Finding.targetId` с изменениями элемента в следующих версиях |
| Попытки записи в модель из помощника | 0 — архитектурно невозможны, проверяется тестом (INV-ADV-004) | `AdvisorResultTest#resultCarriesNoMutations` в CI |
