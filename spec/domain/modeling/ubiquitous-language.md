# Ubiquitous Language: Modeling

Глоссарий, обязательный к использованию в коде, тестах, документации,
коммитах и обсуждениях. Если термин используется в коде на английском,
англоязычная форма — каноническая. Русская форма — для прозы.

Термины ArchiMate (`Element`, `Relationship`, `View`, `Folder`) сохраняют
значение из нотации: расходиться с ArchiMate 3.2 в языке нельзя — архитектор
читает спеку теми же словами, что и стандарт.

## Сущности и агрегаты

| EN | RU | Определение |
|---|---|---|
| **`Workspace`** | Рабочее пространство | Aggregate root. Границы видимости и администрирования: каталог моделей, ACL, настройки. Арендатор системы. |
| **`ArchitectureModel`** | Модель | Aggregate root. Целостная архитектурная модель: дерево папок, элементы, связи, ссылки на представления. Граница согласованности — вся модель целиком: `archi_id` уникален внутри неё, связь не может выйти за её пределы. |
| **`ModelFolder`** | Папка | Entity внутри `ArchitectureModel`. Узел дерева организации. Девять корневых папок фиксированы нотацией, вложенные — произвольные. Папка **часть модели**, а не производная от типа элемента. |
| **`Element`** | Элемент | Entity внутри `ArchitectureModel`. Объект ArchiMate (`ApplicationComponent`, `BusinessProcess`, …). Существует в модели независимо от того, размещён ли он хоть на одном представлении. |
| **`Relationship`** | Связь | Entity внутри `ArchitectureModel`. Направленная связь между двумя элементами одной модели. |
| **`View`** | Представление | Aggregate root. Диаграмма: какие элементы показаны, где и как соединены. Отдельный агрегат, потому что открывается и сохраняется независимо от модели целиком. |
| **`ViewNode`** | Узел представления | Entity внутри `View`. Размещение элемента (или группы, заметки, junction) с геометрией. Координаты **относительны родителю**. |
| **`ViewEdge`** | Ребро представления | Entity внутри `View`. Отрисовка связи: маршрут, изломы, оформление. |
| **`ModelLock`** | Блокировка | Aggregate root. Право одного пользователя редактировать модель в данный момент. |
| **`ModelVersion`** | Версия | Aggregate root. Запись истории: кто, когда, с каким комментарием сохранил, и снимок содержимого (может быть очищен). |
| **`ModelId`**, **`ElementId`**, **`ViewId`** | Идентификаторы | Value objects поверх `UUIDv7`. Внутренние ключи, не покидают систему в составе файлов. |

## Value objects

| EN | RU | Определение |
|---|---|---|
| **`ArchiId`** | Идентификатор Archi | Идентификатор объекта в файле Archi, любой допустимый для Archi. Импортированный сохраняется буквально; новый генерируется как в Archi — `id-<32 hex>`. Уникален в пределах модели, не глобально. |
| **`ArchiType`** | Тип Archi | Строка вида `archimate:ApplicationComponent` — значение `xsi:type` из файла. Не enum: типы вне текущей фазы метамодели тоже должны храниться (FR-03). |
| **`SortOrder`** | Порядок | Позиция узла среди соседей одного родителя. **Разреженная, шаг 1000**: вставка не перенумеровывает соседей. Условие round-trip и условие читаемого diff'а при выгрузке в Git. |
| **`Bounds`** | Геометрия | `x`, `y`, `width`, `height` узла представления. Отсчёт — от родителя, а не от холста. |
| **`PropertyEntry`** | Свойство | Пара `key`/`value`, привязанная к объекту, с собственным порядком. Соответствует `<property>` в файле Archi. |
| **`StyleOverride`** | Переопределение стиля | Собственные `fillColor`, `font`, `fontColor`, `lineColor`, `textAlignment` объекта. Имеет приоритет над токеном слоя (FR-21). |
| **`RawXml`** | Сырой фрагмент | Неразобранный XML неподдержанного узла или атрибута, сохраняемый дословно (FR-03). В `modeling` — непрозрачная строка: интерпретировать её умеет только `interchange`. |
| **`EditorIdentity`** | Редактор | Кто выполняет команду: subject из JWT плюс роли. |

## Состояния

| EN | RU | Описание |
|---|---|---|
| `ACTIVE` | Активна | Модель доступна для чтения и (при наличии блокировки) редактирования. |
| `DELETED` | Удалена | Soft delete: скрыта из каталога, доступна администратору, восстановима. Редактирование запрещено. |
| `PURGED` | Уничтожена | Физическое удаление вместе с версиями. Терминальное состояние, выполняется только администратором явной операцией. Коммиты в Git при этом не переписываются. |

## Что НЕ является частью языка Modeling

- **`ModelDocument`, `RawXmlFragment`, `ImportSession`, `LossReport`** —
  термины BC `interchange`. В `modeling` сырой XML существует только как
  непрозрачное значение `RawXml`, привязанное к объекту; разбирать его
  здесь нельзя.
- **`AdvisorSession`, `Finding`, `ModelPlan`, `TokenBudget`** — термины BC
  `advisor`. Отчёт валидации метамодели (`ValidateModel`) — **не** `Finding`
  помощника: он строится правилами, а не моделью, и живёт в `modeling`.
- **`User`, `Group`, `Realm`** — термины Keycloak. В `modeling` ссылаемся
  только на `EditorIdentity` (subject + роли из токена) и на идентификаторы
  субъектов в ACL как на opaque-значения.
- **Токены визуального стиля, фигуры, иконки** — язык фронтенда.
  `StyleOverride` хранит то, что пришло из файла, и не знает, как это
  выглядит.

Использование терминов из чужих BC внутри Modeling без явной маркировки
«внешний контекст» — ошибка.
