# Бизнес-инварианты Modeling

Каждый инвариант имеет уникальный код вида `INV-MDL-NNN`, где `MDL` —
префикс bounded context'а `modeling`.

Код используется:
- В тестах: `@DisplayName("INV-MDL-001: ...")`.
- В исключениях и в поле `code` ответа `application/problem+json`.
- В логах и метриках (label `error_code`).
- В референсах из ADR и use case'ов.

Коды не переиспользуются: удалённый инвариант помечается `[DEPRECATED]`,
новый получает следующий свободный номер.

---

## INV-MDL-001 — `archi_id` уникален в пределах модели и имеет формат Archi

**Тип:** структурный

**Формулировка:** каждый элемент, связь, представление, узел и ребро
представления, а также каждая папка обязаны иметь непустой `archiId`
формата `id-<24 hex>`. Внутри одной модели `archiId` не повторяется.
Между моделями повторение допустимо и ошибкой не является.

**Нарушение:** два объекта одной модели с одинаковым `archiId` — экспорт
даёт файл, который Archi откроет с потерей одного из них: ссылки
`archimateElement`, `source`, `target` разрешаются неоднозначно.
На уровне хранения перехватывается `UNIQUE (model_id, archi_id)`.

**Тест:** `ArchitectureModelTest#archiIdIsUniqueWithinModel`

## INV-MDL-002 — Жизненный цикл модели идёт только по разрешённым переходам

**Тип:** state-machine

**Формулировка:** модель переходит `ACTIVE → DELETED` (soft delete),
`DELETED → ACTIVE` (восстановление) и `DELETED → PURGED` (физическое
уничтожение администратором). Переход `ACTIVE → PURGED` запрещён.
`PURGED` терминален. В состоянии `DELETED` любая команда изменения
содержимого отклоняется.

**Нарушение:** уничтожение активной модели одной командой — необратимая
потеря без промежуточного состояния, из которого можно вернуться.
Редактирование удалённой модели порождает версии, которых пользователь
не увидит.

**Тест:** `ArchitectureModelStateMachineTest#onlyAllowedTransitionsArePermitted`

---

## INV-MDL-003 — Повтор команды с тем же ключом идемпотентности не меняет состояние

**Тип:** идемпотентность

**Формулировка:** команда изменения, поданная повторно с тем же
`Idempotency-Key` и тем же телом, возвращает результат первого выполнения
и не создаёт ни нового объекта, ни новой версии модели. Тот же ключ с
другим телом — конфликт, а не новое выполнение.

**Нарушение:** повторная отправка при обрыве сети или ретрае прокси
удваивает элемент или версию. Восстановить исходное состояние после
этого можно только откатом, то есть потерей параллельных правок.

**Тест:** `IdempotentCommandTest#replayReturnsFirstResultWithoutNewVersion`

---

## INV-MDL-004 — Связь соединяет элементы своей модели, элемент со связями не удаляется

**Тип:** структурный (ссылочная целостность)

**Формулировка:** `sourceId` и `targetId` связи указывают на элементы той же
модели. Удаление элемента, у которого есть хотя бы одна связь, отклоняется:
сначала удаляются связи. Каскадного удаления нет.

**Нарушение:** висячая ссылка в экспортированном файле — Archi открывает
модель с ошибкой. Каскад же тихо уничтожает связи, которых архитектор не
видел в момент удаления; поведение Archi здесь такое же — явное удаление.

**Тест:** `RelationshipIntegrityTest#deletingConnectedElementIsRejected`

---

## INV-MDL-005 — Порядок узлов разреженный и уникальный в пределах родителя

**Тип:** структурный (условие round-trip)

**Формулировка:** `sortOrder` уникален среди узлов одного родителя.
Нумерация разреженная с шагом 1000; вставка между соседями занимает
середину зазора и не изменяет `sortOrder` других узлов. Перебалансировка
ветви допустима только при исчерпании зазора.

**Нарушение:** плотная нумерация заставляет вставку перенумеровывать всех
соседей — round-trip формально сохраняется, но выгрузка в Git даёт diff на
всю папку вместо одной строки, и ревью становится нечитаемым
([`docs/database.md` §11.6](../../../docs/database.md#116-что-нужно-сделать-уже-на-этапе-1)).

**Тест:** `SortOrderTest#insertDoesNotRenumberSiblings`

## INV-MDL-006 — Запись требует действующей блокировки, принадлежащей автору команды

**Тип:** жизненный цикл (конкурентный доступ)

**Формулировка:** любая команда изменения модели или её представлений
выполняется, только если на модели есть блокировка в состоянии `HELD`,
её владелец совпадает с автором команды, а `expiresAt` не наступил.
Одновременно существует не более одной блокировки на модель.
Администратор снимает чужую блокировку явной командой (FR-05).
Конкурентное сохранение без блокировки отклоняется с `409 Conflict`
и не перезаписывает чужие правки (NFR-07).

**Нарушение:** две параллельные сессии сохраняют модель, и правки той,
что финишировала раньше, исчезают без следа в истории.

**Тест:** `ModelLockTest#writeWithoutHeldLockIsRejected`,
`ModelLockTest#expiredLockGrantsNoWriteAccess`

---

## INV-MDL-007 — Новая связь допустима по матрице ArchiMate 3.2

**Тип:** доменное правило

**Формулировка:** при создании связи тип проверяется по матрице допустимых
связей ArchiMate 3.2 для пары (тип источника, тип цели). Недопустимый тип
отклоняется. **Импортированные** модели этому правилу не подчиняются:
нарушения не блокируют импорт, а попадают в отчёт валидации (FR-10).

**Нарушение:** если применять правило к импорту, реальные модели перестают
открываться — в них есть исторические нарушения, и продукт, отказывающийся
показывать существующую модель, бесполезен. Если не применять к созданию —
редактор молча производит невалидный ArchiMate.

**Тест:** `RelationMatrixTest#forbiddenRelationIsRejectedOnCreate`,
`RelationMatrixTest#importedViolationIsReportedNotRejected`

## INV-MDL-008 — Узел представления ссылается на объект своей модели

**Тип:** структурный

**Формулировка:** `ViewNode` вида `DIAGRAM_OBJECT` обязан иметь `elementId`,
указывающий на элемент той же модели, что и представление. У видов `GROUP`,
`NOTE`, `JUNCTION` поле `elementId` пусто. `ViewEdge` соединяет узлы того же
представления; если `relationshipId` задан, связь принадлежит той же модели.
Геометрия узла отсчитывается от родителя.

**Нарушение:** узел, ссылающийся в пустоту, ломает экспорт и рендер канвы.
Абсолютные координаты у вложенного узла рассыпают компоновку при
перемещении группы.

**Тест:** `ViewIntegrityTest#diagramObjectRequiresElementOfSameModel`

---

## INV-MDL-009 — Дерево папок корректно: восемь корней, без циклов, с раскладкой по видам

**Тип:** структурный

**Формулировка:** у каждой модели существуют все восемь корневых папок
Archi (`strategy`, `business`, `application`, `technology`, `motivation`,
`other`, `relations`, `diagrams`), и они неудалимы. Пользовательские папки
образуют дерево без циклов, `folderType` у них не задан. Связи лежат в
поддереве `relations`, представления — в поддереве `diagrams`.

**Нарушение:** отсутствующая корневая папка или элемент не в своём
поддереве дают файл, который Archi открывает с перекладкой объектов, —
round-trip ломается на структуре, а не на содержимом.

**Тест:** `FolderTreeTest#eightRootFoldersAlwaysExist`,
`FolderTreeTest#moveIntoOwnSubtreeIsRejected`

---

## INV-MDL-010 — Версия неизменяема, номера монотонны, снимок чистится только при настроенном Git

**Тип:** жизненный цикл

**Формулировка:** `versionNo` в пределах модели строго возрастает и не
переиспользуется. Запись версии после создания неизменяема, кроме поля
`label` и обнуления `snapshot`. Обнуление снимка допустимо только для
рабочего пространства, где репозиторий Git настроен и доступен, и только
для версий вне правил хранения (последние 30 дней, помеченные, последняя
за календарный месяц) — FR-46…FR-48.

**Нарушение:** очистка снимка без Git уничтожает единственную копию
содержимого: запись в истории останется, а восстановить по ней будет
нечего.

**Тест:** `ModelVersionTest#versionNumbersAreMonotonic`,
`SnapshotRetentionTest#purgeIsDisabledWithoutGitBinding`

выше становится исполнимой на этапе 2.
