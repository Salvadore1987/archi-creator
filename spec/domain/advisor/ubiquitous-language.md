# Ubiquitous Language: Advisor

Глоссарий, обязательный к использованию в коде, тестах, документации,
коммитах и обсуждениях. Английская форма — каноническая, русская — для прозы.

Язык этого BC — язык **обращения и ответа**: сессия, контекст, находка,
расход. Модель здесь не редактируется и даже не хранится — она приходит
усечённым снимком и уходит вместе с ответом.

## Сущности и агрегаты

| EN | RU | Определение |
|---|---|---|
| **`AdvisorSession`** | Сессия помощника | Aggregate root. Одно обращение к помощнику: функция, контекст, поток ответа, расход токенов, итог. Существует и у отклонённых обращений — аудит пишется всегда (FR-27). |
| **`TokenBudget`** | Бюджет токенов | Aggregate root. Месячный лимит рабочего пространства и накопленный расход. Отдельный агрегат: его состояние меняется от каждой сессии и решает, начнётся ли следующая (FR-51…FR-53). |
| **`AuditEntry`** | Запись аудита | Entity внутри `AdvisorSession`. Кто, когда, какую функцию вызвал и сколько это стоило. |
| **`Finding`** | Находка | Entity внутри `AdvisorSession`. Одно замечание ревью: уровень, описание, ссылка на объект модели, предложение исправления. |

## Value objects

| EN | RU | Определение |
|---|---|---|
| **`ModelContext`** | Контекст модели | Усечённое представление модели, собранное под конкретную функцию: типы, имена, связи, документация — ровно столько, сколько нужно ответу. **Анти-коррупционный слой**: доменная модель ArchiMate не попадает в промпт как есть. Неизменяем, живёт одну сессию. |
| **`AdvisorFunction`** | Функция помощника | Что именно запрошено: ревью, подсказка, план, документация. Определяет форму контекста, форму результата и лимиты. |
| **`ModelPlan`** | План модели | Результат функции `PLAN`: список предлагаемых элементов с типами и список связей между ними. **Описание, а не изменение** (FR-22, FR-25). |
| **`AdvisorAnswer`** | Ответ помощника | Результат функций `EXPLAIN` и `DOCUMENT`: текст в Markdown со ссылками на объекты модели. |
| **`TokenUsage`** | Расход токенов | Пара «входные / выходные токены» одного обращения. |
| **`BudgetPeriod`** | Период бюджета | Календарный месяц в форме `YYYY-MM`. Единица учёта и сброса лимита. |
| **`ElementRef`** | Ссылка на объект | `archiId` объекта модели плюс его отображаемое имя. То единственное, чем помощник указывает на модель: идентификатор для перехода, имя для читаемости. |
| **`WorkspaceId`**, **`ModelId`**, **`ViewId`** | Внешние идентификаторы | Opaque-значения BC `modeling`. |

## Состояния

### `AdvisorSession`

| EN | RU | Описание |
|---|---|---|
| `REQUESTED` | Запрошена | Обращение принято, проверки лимитов ещё не пройдены. |
| `STREAMING` | Отдаётся | Ответ идёт потоком клиенту. |
| `COMPLETED` | Завершена | Ответ получен целиком, расход учтён. Терминальна. |
| `FAILED` | Не выполнена | Внешний сервис недоступен, превышен таймаут, ответ не разобран. Терминальна; израсходованные токены учитываются всё равно. |
| `REJECTED` | Отклонена | Помощник выключен администратором или бюджет исчерпан. Терминальна; токены не расходуются, запись аудита создаётся. |

### `TokenBudget`

| EN | RU | Описание |
|---|---|---|
| `OK` | В норме | Израсходовано менее 80 % лимита. |
| `WARNING` | Предупреждение | Израсходовано 80 % и более: администратор уведомлён, работа продолжается. |
| `EXHAUSTED` | Исчерпан | Израсходовано 100 %: новые сессии отклоняются до следующего периода. |

## Доменные действия (commands)

| EN | RU |
|---|---|
| `ReviewModel` | Провести ревью модели |
| `ExplainElement` | Объяснить выбранный элемент и допустимые связи |
| `PlanModel` | Построить план модели по текстовому описанию |
| `GenerateDocumentation` | Сгенерировать документацию по модели или представлению |
| `RecordTokenUsage` | Учесть расход токенов в бюджете |
| `SetTokenBudget` | Задать месячный лимит рабочего пространства |
| `ToggleAdvisor` | Включить или выключить помощника в рабочем пространстве |

## Доменные события

| EN | RU |
|---|---|
| `AdvisorSessionCompleted` | Сессия завершена, расход учтён |
| `TokenBudgetThresholdReached` | Расход достиг 80 % месячного лимита |
| `TokenBudgetExhausted` | Месячный лимит исчерпан, новые обращения отклоняются |

## Что НЕ является частью языка Advisor

- **`Element`, `Relationship`, `View`, `ArchitectureModel`** — термины BC
  `modeling`. Внутри `advisor` модель существует только как `ModelContext`
  и `ElementRef`: собственной копии доменной модели здесь нет и быть не
  должно, иначе анти-коррупционный слой теряет смысл.
- **Отчёт валидации метамодели** — результат `ValidateModel` из `modeling`.
  Он строится правилами и работает без ИИ. `Finding` помощника — другое:
  она про то, чего формальные правила не ловят.
- **`ImportFinding`, `LossEntry`** — термины BC `interchange`.
- **Промпт, токенизатор, температура, модель `claude-sonnet-5`** — детали
  реализации порта, а не доменный язык. В домене есть `ModelContext` на
  входе, `TokenUsage` на выходе и порт между ними.

Использование терминов из чужих BC внутри Advisor без явной маркировки
«внешний контекст» — ошибка.
