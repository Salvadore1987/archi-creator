# ADR-0017 — Типизированные столбцы и непрозрачный остаток XML

## Статус

Принято 2026-10-08, этап 2. Следует из FR-02, FR-03 и NFR-05.

## Контекст

PostgreSQL — источник правды, `.archimate` — результат сериализации
([§4.3](../../docs/database.md#43-стратегия-хранения)). Значит, цикл «импорт →
таблицы → экспорт» обязан давать семантически тот же файл (`INV-IXC-005`),
и каждая мелочь файла должна где-то лежать в базе.

Мелочей много, и большинство метамодели не нужно:

- атрибуты оформления, которых нет в `StyleOverride`: `alpha`, `lineWidth`,
  `gradient`, `textPosition`, `iconColor`, `borderType`, `deriveElementLineColor`;
- `feature`, `profile`, `profiles`, `strength` у влияния, `connectionRouterType`
  у представления, `documentation` и `property` у папок;
- узлы расширений с чужим пространством имён внутри элемента (`INV-IXC-001`);
- порядок всего перечисленного среди соседей и порядок атрибутов.

Завести столбец под каждую мелочь значит гнаться за Archi: новая версия
редактора добавит атрибут, и round-trip сломается на файле, которого схема
не знает. Хранить объект целиком строкой XML значит потерять то, ради чего
есть база: редактирование, ссылки по ключам, выборки по типу.

## Решение

Каждая строка с `archi_id` — модель, папка, элемент, связь, представление,
узел и ребро представления — хранит две части.

**Типизированные столбцы** — то, что описано полями в
[`aggregates.yaml`](../domain/modeling/aggregates.yaml): имя, тип, документация,
свойства, концы связи, геометрия, собственный стиль. Это правда о значении:
их правит редактор, по ним строятся ссылки и выборки.

**Остаток XML** (`raw_xml`, `RawXml`) — всё остальное, в форме, которую
задаёт и читает только interchange:

- порядок атрибутов узла; на месте типизированного атрибута — метка без значения,
  незнакомый атрибут — с значением;
- содержимое узла без идентификатора — `documentation`, `property`, `bounds`,
  `bendpoint`, `content`, непрозрачные фрагменты — с позицией в разреженной
  нумерации родителя, общей с `sort_order` дочерних строк. Типизированное
  значение оставляет в остатке только метку места («здесь была документация»),
  нетипизированное лежит целиком.

modeling остаток хранит и не разбирает. При выгрузке interchange накладывает
столбцы на остаток: **столбец сильнее остатка**. Пропавшее типизированное
значение убирается, новое встаёт на место по умолчанию — туда же, куда его
поставил бы Archi. Значение, которое не проходит проверку домена (цвет
не `#rrggbb`, свойство без `value`), в столбец не идёт и остаётся в остатке
дословно: домен не обязан понимать всё, что лежит в файле.

Дочерние объекты остатка не касаются: их позиция — собственный `sort_order`
в той же нумерации, что у меток остатка. Рёбра лежат в содержимом своего
источника — так их пишет Archi (`sourceConnection` внутри узла).

`targetConnections` производен: множество берётся из рёбер, порядок —
из остатка для тех, что остались, новые дописываются в порядке рёбер
([§3.4](../../docs/backend.md#34-кодек-archimate--ключевые-решения), п. 6).

## Последствия

- Схема не знает Archi целиком и не обязана: незнакомое переживает round-trip
  без миграции (FR-03).
- Позиция типизированного значения в файле не теряется, а новое значение
  не требует пересчёта позиций соседей (`INV-MDL-005`).
- Цена — второе место правды для атрибутов, которые типизированы и одновременно
  отмечены в остатке. Правило «столбец сильнее остатка» снимает конфликт,
  но его обязан соблюдать каждый, кто пишет в `raw_xml`: правка остатка
  в обход interchange запрещена.
- Остаток формата interchange — значит, Git-выгрузка 7a читает его тем же кодом,
  что и экспорт `.archimate`, а не вторым разбором.

## Отклонённые варианты

| Вариант | Почему нет |
|---|---|
| Столбец на каждый атрибут Archi | Гонка за редактором; первый же неизвестный атрибут ломает round-trip |
| Объект целиком строкой XML | Нет ни редактирования, ни ссылок, ни выборок — база превращается в файловое хранилище |
| Таблица «узел — атрибут — значение» | Тот же XML, разложенный по строкам: тысячи строк на модель и ни одного выигрыша перед остатком |
| Хранить исходный файл рядом с таблицами | Две правды: после первой правки файл и таблицы расходятся, и непонятно, какая выгружается |
