# ADR-0030 — Списки моделей и пространств без пагинации

## Статус

Принято 2026-10-21 по итогам этапа 11 ревью кода (`docs/review/11-rest.md`, находка 11-05,
отклонение D-16). Отступает от внутреннего стандарта `java-spring-code-guidelines-v2.md`
(версия 3.0) в §4.1.4 (пагинация коллекционных endpoint'ов) для двух списков.

## Контекст

Стандарт требует у каждого коллекционного endpoint'а пагинацию с размером по умолчанию
и жёстким максимумом. В API три списка, которые не выводятся из одной модели:

- `GET /models/{id}/versions` — история версий: каждое сохранение добавляет строку,
  и список растёт без предела;
- `GET /models` — модели пространства: в банке их десятки, интерфейс показывает все сразу
  (выбор модели, дерево);
- `GET /workspaces` — пространства: до мультиарендности оно одно.

Остальные выборки — содержимое одной модели (дерево, представление, отчёт проверки,
список доступа) — отдаются целиком по смыслу: клиент строит из них холст и дерево.

## Рассматриваемые варианты

**1. Пагинация у всех трёх.** Список моделей и пространств пришлось бы собирать в интерфейсе
постранично ради выборки, которая и так помещается в один ответ; размер по умолчанию либо
не ограничивал бы ничего, либо молча обрезал бы список.

**2. Пагинация только там, где список растёт без предела.** История версий — страницами;
модели и пространства — целиком, пока их число ограничено устройством продукта.

## Решение

Вариант 2.

- **История версий** — страница: `size` (по умолчанию 50, больше 200 не отдаётся) и `before` —
  номер версии, с которой продолжить к старым. Тело — массив, как и раньше: последняя версия
  по-прежнему первая. Умолчание и предел живут в сценарии (`VersionListQueryHandler`).
- **Модели и пространства** отдаются целиком.

## Последствия

- Находка ревью «нет пагинации» у `GET /models` и `GET /workspaces` не заводится.
- Решение пересматривается, когда появится мультиарендность (пространств станет много) или
  модель перестанет быть единицей, которую интерфейс показывает списком: тогда эти списки
  получают страницы тем же способом, что история версий.
