# ADR-0026 — Значения из требований — в YAML, окружением — секреты и адреса

## Статус

Принято 2026-10-14 по итогам этапа 0 ревью кода (отклонение D-10). Отступает
от внутреннего стандарта `java-spring-code-guidelines-v2.md` в §2.1.5 и §4.6.2.

## Контекст

Стандарт запрещает константы в YAML: каждое значение — переменная окружения,
`application.yml` только ссылается на неё.

В проекте окружением приходят секреты (`ARCHI_DB_PASSWORD`, `ANTHROPIC_API_KEY`) и всё,
что зависит от стенда: адреса базы и Keycloak, каталог Git-кэша, модель и адрес API
помощника, часовой пояс бюджета. В `prod` у секретов и адресов умолчаний нет — приложение
не стартует без них. Константами в `application.yaml` записаны числа, которые
**не зависят от стенда**, а заданы требованиями в `spec/nfr/<bc>.yaml`: пул соединений
и таймаут запроса, частота обращений к помощнику, граница контекста, доля покрытия,
срок блокировки, лимит токенов по умолчанию.

Число из требования, вынесенное в переменную окружения, получает второй источник правды:
спека говорит одно, стенд — другое, и расхождение не видно ни в диффе, ни в тестах.

## Решение

- **Окружением задаётся то, что различается между стендами, и секреты.** Секрет
  и обязательный адрес в `prod` — без значения по умолчанию.
- **Значение из требования записывается в `application.yaml` числом** рядом с комментарием,
  что оно означает; меняется оно правкой `spec/nfr/` и YAML в одном коммите.
- Переопределить такое значение на стенде можно стандартным механизмом Spring Boot
  (переменная `ARCHI_AI_USERREQUESTSPERMINUTE` и т. п. перекрывает свойство и без ссылки
  в YAML) — это аварийный рычаг, а не способ настройки.
- **Текст для пользователя в YAML не пишется** — он ключ ресурса локали, по правилу
  локализации проекта.
- Читается конфигурация только через `@ConfigurationProperties` — запрет `@Value`
  из стандарта действует полностью.

## Последствия

- Находки ревью «константа в YAML» не заводятся для значений из `spec/nfr/`. Заводятся:
  значение, которое расходится со спекой; зависящее от стенда значение без переменной;
  секрет с умолчанием; текст для пользователя в YAML (`archi.modeling.default-workspace-name`).
- Сверку YAML со `spec/nfr/` сейчас никто не держит; известное расхождение — пул
  соединений interchange (в спеке отдельный, 8 соединений и таймаут запроса 120 с,
  в приложении — общий пул на 20 и 15 с). Решение владельца 2026-10-14: **правится спека**
  — пул один, потому что импорт пишет таблицы modeling в транзакции `UnitOfWork`
  (`ADR-0024`) и второй пул разорвал бы её; канву от длинного импорта защищает предел
  одновременных импортов, а таймаут запроса поднимается точечно для импорта.
