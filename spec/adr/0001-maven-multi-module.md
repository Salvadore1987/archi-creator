# ADR-0001 — Разделение реализации на Maven-модули вместо пакетов одного модуля

## Статус

Принято 2026-09-22. Не реализовано: корневой `pom.xml` пока одномодульный,
перекройка — работа этапа 0.

## Контекст

Спецификация требует, чтобы доменный слой не знал о фреймворке: `domain/<bc>/`
описан как чистая модель без Spring и JPA. Такую границу можно держать двумя
способами — соглашением (пакеты `domain`, `application`, `adapter` внутри одного
модуля плюс проверки ArchUnit) или сборкой (отдельные Maven-модули со своими
зависимостями).

Проект на этапе 0: кода нет, `pom.xml` — голый Maven без зависимостей. Цена
решения сейчас минимальна, через три этапа — это переезд всего дерева исходников.

## Решение

Отдельные Maven-модули на слой и bounded context:

| Слой спеки | Модуль | Зависимости |
|---|---|---|
| `domain/<bc>/` | `archi-<bc>-domain` | нет (чистый Java) |
| `application/<bc>/` | `archi-<bc>-application` | `archi-<bc>-domain` |
| `contracts/<bc>/` | `archi-<bc>-adapter-rest` | application |
| — | `archi-<bc>-adapter-persistence` | application |
| `nfr/<bc>.yaml` | `archi-bootstrap` | все модули, Spring Boot |

## Последствия

**Хорошие.** Граница держится компилятором: у `archi-<bc>-domain` в `pom.xml`
нет ни Spring, ни JPA, поэтому `@Entity` в доменном классе не собирается.
Нарушение обнаруживается на сборке, а не на ревью и не в отчёте ArchUnit,
который можно отключить.

**Плохие.** Сборка дольше, дерево модулей многословнее, простая правка иногда
задевает три `pom.xml`. Импорт в IDE тяжелее. Для одной команды из нескольких
человек это заметные накладные расходы.

**Что становится обязательным.** Перекройка корневого `pom.xml` в multi-module
до начала этапа 1: начинать кодек в одномодульном проекте значит сделать переезд
позже и дороже.

## Отвергнутая альтернатива

**Пакеты одного модуля плюс ArchUnit.** Дешевле в старте и привычнее. Отвергнуто
потому, что держится на дисциплине: правило ArchUnit можно пометить `@Disabled`
под давлением срока, и первое же такое исключение размывает границу необратимо.
Здесь цена ошибки выше обычной — на границе `interchange` стоит lossless
round-trip, контур, который ломается незаметно.
