# Archi Creator

Веб-редактор архитектурных моделей на базе нотации **ArchiMate 3.2**: drag-and-drop-канва,
ИИ-помощник и полная совместимость с нативным форматом Archi (`.archimate`).

Продукт не клонирует Archi — он берёт его семантику и файловый формат, но даёт более
качественный визуальный язык и встроенного советника, который объясняет нотацию и находит
ошибки в модели. Результат остаётся обычным `.archimate`-файлом и открывается в Archi без
потерь: нет vendor lock-in, инструмент внедряется постепенно, рядом с существующим Archi.

## Статус

**Этап 0 — каркас.** В репозитории пока лежат спецификация, макеты интерфейса на реальных
данных и заготовка Maven-проекта (`Main.java`). Приложение ещё не собирается как сервис:
ни Spring Boot, ни фронтенд-модуля в `pom.xml` нет.

Что уже готово и служит входом в разработку:

- полная спецификация (требования, архитектура, API, схема БД, визуальный язык) — см. ниже;
- интерактивные макеты трёх компоновок главного экрана, вариант **A «Панели»** выбран;
- референсная модель `docs/Hamkorbank_AS_IS_strict.archimate` (~400 элементов, ~370 связей,
  12 представлений) — на ней разрабатываются и тестируются кодек и канва.

## Макеты

Статические, без сборки — открываются файлом в браузере:

```
open docs/mockups/index.html
```

Три варианта компоновки главного экрана (`layout-a-panels.html`, `layout-b-canvas.html`,
`layout-c-modes.html`) на данных реальной модели. Выбран вариант **A «Панели»**
([§6.5](docs/spec/frontend.md#65-компоновка-главного-экрана--решение-принято)).

## Стек

| Слой | Технология |
|------|-----------|
| Язык бэкенда | Java 25 |
| Фреймворк | Spring Boot 4.x (Web, Data JPA, Security OAuth2 Resource Server, Validation) |
| БД | PostgreSQL 16, миграции — Flyway |
| Аутентификация | Keycloak 26, OIDC, JWT |
| XML | StAX на чтение, DOM/StAX-writer на запись с сохранением порядка |
| Фронтенд | React 19 + TypeScript, Vite |
| Канва | React Flow (`@xyflow/react`), узлы — собственные SVG-компоненты |
| Состояние | Zustand (документ модели) + TanStack Query (серверные данные) |
| Стили | CSS-переменные (токены) + CSS Modules |
| Экспорт картинок | Собственный `SvgWriter` на Java + Apache Batik |
| ИИ | Anthropic API, модель `claude-sonnet-5`, потоковая отдача (SSE) |
| Тесты | JUnit 5, Testcontainers, Playwright |
| Сборка/деплой | Maven, Docker Compose |

Фронтенд собирается тем же Maven-прогоном (`frontend-maven-plugin`) и укладывается в jar —
на выходе один артефакт.

## Сборка

Сейчас доступна только компиляция заготовки:

```
mvn clean package
```

Целевая сборка по [§10.2](docs/archi-creator.md#102-сборка), когда появятся модули:

```
mvn clean package          # npm ci && npm run build → target/classes/static, затем repackage
docker compose build && docker compose up -d
```

Требуется JDK 25 и Maven 3.9+.

## Принципы, которые стоит знать до первого коммита

- **Lossless round-trip — критический контур.** Цикл «открыть → ничего не менять → сохранить»
  обязан давать семантически идентичный XML. Проверяется golden-file-тестами на каждом
  коммите, регрессия блокирует сборку
  ([§9.1](docs/spec/backend.md#91-golden-file-тесты-round-trip--критический-контур)).
- **Неизвестное не теряется.** Элементы и связи вне текущей фазы метамодели хранятся
  как opaque-узлы и отдаются при экспорте как есть (FR-03).
- **ИИ не меняет модель.** Любой его результат — текст, ссылки и подсказки; правки вносит
  только архитектор (FR-22).
- **Источник правды — база, а не Git.** Git-выгрузка (разложенный YAML) нужна для журнала
  и ревью; слияние — по сущностям через стабильные идентификаторы, текстовое слияние YAML
  запрещено ([§11](docs/spec/backend.md#11-git-интеграция-и-формат-хранения)).
- **Ключ Anthropic живёт только на сервере** и никогда не попадает в браузер (NFR-06).
