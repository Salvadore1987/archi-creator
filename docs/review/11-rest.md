# Этап 11. REST-адаптеры

**Дата:** 2026-10-21. **Репозиторий:** ветка `cr_phase_11`, после `014340a` (исправления этапа 10).
**Стандарт:** коммит `97bce16`, §3.3.8.2 (REST-адаптер), §4.1 (REST API), §4.2 (валидация),
§4.3.2–4.3.4 (ошибки), §6.6 (Web в 4.x), §6.8 (Jackson 3), чеклист §5.3.
**Объём:** три модуля `*-adapter-rest` — 22 файла, ~2,3 тыс. строк; прочитаны целиком, без субагентов.
Точечно сверены: `CommonProblemHandler` (bootstrap — обработчик ошибок REST-слоя), `ErrorCodes`,
`application.yaml` (`spring.mvc`, `server.error`), `AdvisorSessionStartCommandHandler.LiveStream`,
`PropertyEntry`, `RestLayerConventionsTest`, `LocalizedProblemIT`, ADR-0022, пути и статусы трёх
`spec/contracts/*/rest-api.openapi.yaml`, `frontend/src/api/endpoints.ts`.

Гипотезы 11-01…11-04 проверены живым прогоном (временный `*IT` на MockMvc, удалён): ответы приведены в «Сути».

## Что проверено и в порядке

- **Контроллеры — один вызов сценария.** Каждый обработчик зовёт один метод входного порта; ветвления
  по значению запроса нет. `switch` по исходу импорта и `created() ? 201 : 200` — перевод результата
  сценария в статус, решение принято в сценарии. Умолчаний со смыслом нет: «не задано» уходит `null`
  (пространство, формат и параметры выгрузки, папка). `null` значения свойства — `""` при переводе:
  домен свойства без значения не знает, читатель файла даёт ту же пустую строку.
- **Отказ импорта собирается в контроллере** (`InterchangeController.rejected`) — исключения
  §4.3.4 №5 нет: отказ — исход сценария с записанной сессией, а не исключение; тело собирает тот же
  `InterchangeProblemHandler.problem`.
- **DTO** — записи в `…adapter.rest.dto`, держатель `Dtos` в каждом модуле; агрегаты и сущности JPA
  наружу не выходят (`RestLayerConventionsTest`, `ApplicationLayerTest`). Jackson 3 (`tools.jackson`),
  `Optional` в DTO нет.
- **URL и версия** — `/api/v1` во всех трёх модулях (D-11), существительные во множественном числе,
  дефисы, без завершающего слэша; действия — подресурсом (`/restore`, `/purge`, `/tree/move`, `/git/push`).
  Методы и статусы по таблице §4.1.3: удаление — `204`, создание — `201`, повтор ключа — `200`.
- **Чувствительное не в URL.** Токен Git — ссылкой `env:ИМЯ` в теле `PUT /git-binding`, текст для
  помощника — в теле; в пути и запросе — только UUID, номера версий и параметры выгрузки.
- **Обработчики ошибок контекстов** — `problem+json` с `code` и текстом по `Accept-Language` (D-03);
  `500` — только дефект выгрузки и испорченный снимок (D-04), подробность — в журнал. `Retry-After`
  у превышения частоты помощника.
- **SSE помощника.** Поток читается в фоне `applicationTaskExecutor`, поток запроса свободен; уход
  клиента сценарий ловит сам (`LiveStream.run` — расход списывается, итог шлётся, если есть кому);
  после истечения срока следующий кадр падает, и сценарий отменяет внешний поток. Срок — 11-08.
