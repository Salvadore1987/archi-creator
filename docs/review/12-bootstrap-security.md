# Этап 12. Bootstrap: проводка, конфигурация, безопасность

**Дата:** 2026-10-21. **Репозиторий:** ветка `cr_phase_12`, после `34eb529` (исправления этапа 11).
**Стандарт:** коммит `97bce16`, §3.3.9 (bootstrap), §4.6 (конфигурация), §4.13 (безопасность),
§6.5 (конфигурация в 4.x), §6.11 (Spring Security 7), §4.4.7 (MDC), чеклист §5.3.

без субагентов. Точечно сверены: `AiSettings`, `GitSettings` (настройки этапа 13 — только на валидацию),

## Что проверено и в порядке

- **Бины domain и application — `@Bean`, не сканирование** (§3.3.9 №1, §2.10). Сценарии трёх контекстов
  собираются конструкторами в `wiring/*Configuration`; в application-слоях Spring нет (enforcer).
  Сканируются только адаптеры (`@Repository`, контроллеры) и `MessageSourceTexts` — реализация порта текстов.
  Бизнес-логики в конфигурациях нет; `defaultWorkspace` и проход очереди Git только вызывают входные порты.
- **`@Value` нет нигде** (§4.6.4, §6.5.1); настройки — record'ы `@ConfigurationProperties` с умолчаниями
  `@DefaultValue` (кроме `InterchangeSettings` — 12-04).
- **YAML.** Константы требований — в YAML по `ADR-0026` (D-10); адреса — переменными с умолчанием,
  секреты (`ARCHI_DB_PASSWORD`, `ANTHROPIC_API_KEY`) без умолчания в общем и `prod`; пароль-умолчание только
  в `dev`. `ddl-auto: validate`, `open-in-view: false`, `whitelabel` выключен.
- **Профили** — только по среде, `dev` и `prod` (§6.5.2 №1); `@Profile` лишь на конфигурациях безопасности
  (№4). Без профиля включается настоящая цепочка — по умолчанию закрыто.
- **Spring Security 7** — lambda DSL, `PathPatternRequestMatcher` по умолчанию, ресурс-сервер JWT,
  `STATELESS`; CSRF выключен обоснованно — токен в заголовке, сессии нет. Заголовки безопасности по умолчанию
  не отключены (§6.11 №8). Роли проверяются на границе use case'а по таблицам `spec/nfr/<bc>.yaml`, а не
  в матчерах URL — отступление от §6.11 №5 (`@PreAuthorize`), не записанное в ADR (12-12).
- **CORS** — закрыт по умолчанию и в `prod`, список источников без учётных данных; в `dev` — адрес Vite.
- **MDC** — три ключа, удаление в `finally` (§4.4.7); персональных данных нет — только `sub`.
  Порядок фильтра — 12-03.
- **Заглушка `dev`** — контекст безопасности ставится на запрос и снимается в `finally`, роль одна,
  `ARCHITECT`: операции `ADMIN` в `dev` недоступны, как в бою.
