вызовы сразу проходили проверку. Actuator (7, 8) — в конце: перенос порта меняет состав и CI.

## Расхождения плана с фактом

- **Задача 1.** Трассировку не добавляли, а записали пробелом: без коллектора в составе спанам некуда уходить,
  а экспортёр OTLP по умолчанию стучался бы в `localhost:4318` и засорял журнал отказами. Доля выборки
  в спеке была своя у каждого контекста (0,1, 0,5, 1,0) — в одном процессе выборка одна, это решается
  вместе с включением. У ключей Keycloak в спеке остались таймаут (его держит задача 6) и кэш; два повтора
  и предохранитель убраны с причиной. Проверка — не тест, а сверка числа в задаче 6: на старом коде
  настройки таймаута нет.

- **Задача 2.** Уровни выбраны по смыслу записи: сбой прохода очереди, отказ публикации записи, нечитаемые
  позиции в коммите, недоступный API помощника, обрыв потока и исчерпанный бюджет — `ERROR`; порог бюджета
  и неразобранный запрос — `INFO` (это ход работы, а не повод для вмешательства). `slf4j-api` добавлен
  в application interchange и advisor — граница слоя его допускает: запрет касается Spring, JPA и Hibernate,
  а не API журнала. Проверка склейки — по исходникам: поле журнала в проекте одно имя, `LOG`. На старом коде
  падали все три проверки: 12 зависимостей от `System.Logger`, 5 вызовов `debug`/`warn`, 2 склейки.
- **Задача 3.** Декоратор — свой, а не `ContextPropagatingTaskDecorator`: тот требует библиотеки
  `context-propagation` и регистрации MDC в ней, а нужен один MDC. Boot сам ставит бин `TaskDecorator`
  на `applicationTaskExecutor`; это и проверяет IT — на старом коде задача видела пустой `traceId`.
