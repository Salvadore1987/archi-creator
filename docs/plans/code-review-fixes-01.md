# Исправления по этапу 1 ревью

**Запрос от 2026-10-15:** «нужно исправить все несостыковки; сложность методов может быть до 25».
Находки — [`docs/review/01-mekhanicheskie-proverki.md`](../review/01-mekhanicheskie-proverki.md).

План ревью (`code-review.md`) откладывал исправления до этапа 18. Владелец решил чинить
находки этапа 1 сразу: они механические, касаются всей кодовой базы, и следующие этапы
читают код уже без них.

## Решения владельца (2026-10-15)

- **Сложность метода — до 25.** Цель стандарта «≤ 10 для нового кода» сборкой не держится;
  находка 01-11 закрыта решением, а не правкой. Записывается в ADR-0021.
- **Порядок импортов — Google Java Style** (статические, пустая строка, остальные одним
  блоком по алфавиту), как уже написан код. Записывается в ADR-0021 вместо §2.3 стандарта.
- **Javadoc — по стандарту полностью:** публичные типы, публичные и protected методы
  (кроме `@Override` — описание наследуется), публичные константы.

## Расхождения плана с фактом

- **Задача 3.** Пустой `catch` нашёлся и в `JGitRepository` (узкий, с комментарием —
  на этапе 1 не считался находкой). `EmptyCatchBlock` запрещает пустой блок и с комментарием,
  поэтому разбор кандидата вынесен в метод, возвращающий `Optional`; `AdvisorService` пишет
  об ушедшем клиенте строку `INFO`.
- **Задача 8.** `GET /workspaces` по-прежнему отдаёт все пространства через `findAll()`:
  пагинация списка — отклонение D-16 со сменой контракта API, а не находка этапа 1.
  Правило `CodingRulesTest.noUnboundedFindAll` пропускает только `WorkspaceService.list()`
  (список исключений `UNBOUNDED_LIST_CALLERS`); исключение снимается вместе с D-16.

## Отменённые варианты

- **Снизить сложность 15 методов до 10.** Владелец принял предел 25; правка `SvgWriter`,
  `Routing`, `OefWriter` к тому же требует пересъёмки эталонов сверки.
- **Переформатировать импорты в четыре группы стандарта.** 428 файлов; конфликт
  во всех открытых ветках ради порядка, который ничего не меняет в чтении кода.
