# Ревью кода по стандарту Java / Spring Boot

**Запрос от 2026-10-14:** «план code review, разделённый на этапы, чтобы контекст
не расширялся, с чекбоксами; учитывать code guidelines из
`java-spring-code-guidelines-v2.md`».

**Стандарт** — [`java-spring-code-guidelines-v2.md`](https://github.com/Salvadore1987/architecture-and-code/blob/97bce16c379e9c9a02a66628068775579dd7932a/java-spring-code-guidelines-v2.md),
версия 3.0, закреплён на коммите `97bce16` (2026-09-19). Ревью идёт по этому коммиту,
а не по `main`: если стандарт поменяется посреди ревью, находки разных этапов
перестанут быть сравнимы.

**Что ревьюим:** серверный код — 471 файл `src/main/java` (~36 тыс. строк) в 13 модулях,
миграции Flyway, конфигурация, сборка и серверные тесты (~14 тыс. строк). Фронтенд
вне объёма: стандарт про Java и Spring, у фронтенда свои правила (`checks/static-rules.test.ts`).

**Чего ревью не делает:** не правит код. Результат — находки по этапам и в конце
отдельный план исправлений. Правка посреди ревью смешивает «что нашли» и «что сделали»
и раздувает контекст этапа.

## Как устроен этап (протокол экономии контекста)

Каждый этап — **одна сессия**, начинается с `/clear`. В контекст попадает только:

1. разделы этого плана «Как устроен этап», «Формат находок», «Реестр отклонений»
   и блок своего этапа;
2. разделы стандарта, перечисленные у этапа, — **по диапазонам строк**, а не файлом целиком:
   ```bash
   G=https://raw.githubusercontent.com/Salvadore1987/architecture-and-code/97bce16c379e9c9a02a66628068775579dd7932a/java-spring-code-guidelines-v2.md
   curl -sL "$G" -o "$TMPDIR/guidelines.md"          # один раз за сессию
   sed -n '215,311p' "$TMPDIR/guidelines.md"          # нужный раздел
   ```
   Всегда добавляется чеклист §5.3 (строки 6997–7064) — он короткий и задаёт рамку;
3. код своего этапа. Объём больше ~2,5 тыс. строк — пакеты отдаются субагентам
   (Explore или general-purpose) с тем же списком правил, а субагент возвращает
   **только находки** в формате ниже. Находки субагента проверяются по коду
   до записи (правило «код, который писал не я»).

Код соседних модулей читается только по ссылке из находки и точечно (`grep`,
`sed -n` по строкам), не целыми файлами.

**Закрытие этапа:** находки — в `docs/review/NN-<имя>.md`, отметки в этом плане,
новые кандидаты в реестр отклонений — в раздел «Реестр отклонений», один коммит
`docs(plans): ревью — этап NN, <имя>`.

## Формат находок

Файл этапа — `docs/review/NN-<имя>.md`: шапка (дата, коммит репозитория, объём),
затем таблица.

| № | Уровень | Правило | Где | Суть | Предложение | Ловит сборка? |
|---|---|---|---|---|---|---|
| 03-07 | ЗАПРЕЩЕНО | §2.1.1 | `RelationMatrix.java:118` | `var` в локальной переменной | явный тип | нет → Checkstyle |

- **Уровень** — маркер стандарта (§0.2): ЗАПРЕЩЕНО (блокирует merge), ОБЯЗАТЕЛЬНО,
  РЕКОМЕНДУЕТСЯ, плюс **ПРОЕКТ** — нарушение правила самого проекта (`CLAUDE.md`,
  `spec/`), которое стандарт не покрывает.
- **Номер** — `<этап>-<порядковый>`, на него ссылается план исправлений.
- Массовое нарушение одного правила (одно и то же в 40 файлах) — **одна** находка
  со счётчиком и списком файлов в приложении, а не 40 строк.
- Расхождение, уже записанное в реестре отклонений как принятое, находкой не является.
- **Ловит сборка?** — есть ли проверка (ArchUnit, enforcer, скрипт `tools/`, тест).
  Нет — в плане исправлений сначала проверка, потом правка (глобальное правило).

## Отменённые варианты

- **Один проход по всему коду с чеклистом §5.3.** 36 тыс. строк не помещаются в контекст;
  после сжатия находки первых модулей теряются, а последние модули смотрятся бегло.
- **Этапы по разделам стандарта (сначала весь код на §2, потом весь на §3…).** Каждый
  этап снова читал бы весь код. Этапы идут по модулям, а сквозные правила вынесены
  в механический этап 1 и в этап 14 по `grep`.
- **Копия стандарта в репозитории.** 8 тыс. строк чужого документа устареют молча;
  ссылка на закреплённый коммит даёт ту же воспроизводимость.

## Расхождения плана с фактом

- **Этап 0.** D-07 в плане смешивал создание и доставку событий; ADR-0003 решает только
  доставку. Создание событий (агрегат накапливает, `pullEvents()`) перенесено в D-06.
- **Этап 0.** D-03 оказался ближе к стандарту, чем предполагалось: `code` уже идёт
  расширенным свойством `ProblemDetail`. Расходятся строковые коды и место `traceId`.
- **Ошибка этапа 0.** В отчёте было «`traceId` в теле ошибки есть» — неверно: в выводе
  `grep` файлы обработчиков пришли из соседней команды. `traceId` идёт заголовком
  `X-Trace-Id`; исправлено в отчёте и `ADR-0022`. Урок: в одном вызове — одна выборка
  или явные разделители между ними.
- **Этап 0.** Javadoc типов покрыт на 95 %, методов — на ~30 %; `@author` нет нигде.
  D-02 разделён: покрытие — нарушение (этап 1), теги — кандидат в ADR.
- **Этап 1.** `var` — в 13 файлах основного кода, а не в 12, как записано 2026-10-14;
  плюс 11 тестовых. Javadoc посчитан иначе, чем на этапе 0 (вложенные типы включены,
  методы с `@Override` исключены): типы 85 %, методы 50 %. Числа разные, код тот же.
- **Этап 1.** Порядок импортов: проект последовательно держит порядок Google Java Style,
  а ADR-0021 оставляет §2.3 стандарта в силе — противоречие решения и кода, находка 01-09.
- **Этап 1, ложные срабатывания выборок** (чтобы не всплыли заново): `javax.xml.*`
  и `javax.imageio` — пакеты JDK, а не удалённый `javax.*` Jakarta; `setStrictImport` —
  метод порта, не setter injection; `@Autowired` на полях `*IT` — стиль тестов самого стандарта.
- **Этап 1.** Исправления находок вынесены из этапа 18 вперёд по решению владельца
  (2026-10-15): правила механические и сквозные, и следующие этапы читают код уже
  без них. Предел сложности — 25 (ADR-0021), находка 01-11 закрыта решением.
- **Этап 2.** Ревью нашло дефект, внесённый исправлениями этапа 1: задача 14 перевела
  `ArchiIdGenerator` на JUG с системными часами и не обновила Javadoc («случайный UUID») —
  находка 02-11. Урок: правка по правилу проекта читается целиком, вместе с комментарием
  класса и тем, как правило требует брать часы.
- **Этап 2.** Этап шёл в той же сессии, что этап 1 и его исправления, а не после `/clear`:
  код читали субагенты, в основной контекст вернулись только находки.
- **Этап 7, снятые гипотезы** (чтобы не всплыли заново): управляющие символы в именах
  ломали бы XML OEF (`XmlEscaping` их не срезает, в отличие от `Svg.escape`), но домен modeling
