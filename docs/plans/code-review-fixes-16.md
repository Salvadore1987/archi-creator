# Исправления по этапу 16 ревью — тесты

**Основание:** находки [`docs/review/16-testy.md`](../review/16-testy.md);
порядок работы — как в планах этапов 1–15 (владелец 2026-10-22: «если есть изменения — сразу исправь»).

Каждая задача — проверка в сборке (где она механически возможна), прогон на старом коде (обязан упасть),
перенос всех мест, тесты затронутых модулей зелёные, один коммит.

## Порядок

Проверка исходников тестов (1) — первой: она трогает доменные тесты, которые потом правят задачи 3 и 6.
Затем фейки (2), отказы домена (3) и операции REST (4) — у них разные модули, тесты пишутся параллельно
в отдельных рабочих копиях, дифф читается до слияния. Разделение тестов (6) — после 3: те же файлы.
Инфраструктура интеграционных тестов (7) — последней: меняет контекст всех `*IT`.

## Расхождения плана с фактом

- **Задача 1.** Без `@DisplayName` — 9 методов в 2 классах, а не 16 в 7, как записало ревью: первая выборка
  искала аннотацию в окне ±4 строки, и у параметризованных тестов с длинным `@ValueSource`/`@CsvSource` она
  оказалась дальше. Находка поправлена. Время в интеграционных тестах берётся у часов приложения (`Clock`
  в `IntegrationTest`), а не фиксированной константой: блокировка и сессия сравниваются с часами сервера.
- **Задача 8.** Решение записано по умолчанию, без отдельного вопроса владельцу: запас замеров — от 8×
  до 47× от предела (`ADR-0034`, таблица), и вынос в отдельный профиль снял бы проверку NFR-02 и NFR-03
  с каждого коммита. `AdvisorStreamingIT` в решение не вошёл: он проверяет нижнюю границу и на медленной
  машине не падает.
- **Задача 3.** Тесты писали три субагента в отдельных рабочих копиях, по модулю на каждого; дифф прочитан
  до слияния. 78 из 90 строк `throw` получили отказной тест с точным кодом и ключом сообщения; 12 недостижимы
  по построению (SHA-256 есть в каждой JVM, матрица связей и каталог типов — ресурс и код в том же jar, ветки
  `default`, которые вызывающие отсеивают раньше) и помечены строкой `// недостижимо — причина` над `throw`.
  Проверка мерит общий отчёт; `--module` — отчёт юнит-тестов модуля, им пользовались при написании.
  **Ошибка, найденная по ходу:** рабочие копии субагентов создаются от `main`, а не от текущей ветки — патчи
  накладывались трёхсторонним слиянием (`git apply --3way`), один конфликт в `DocumentValuesTest` разрешён руками.
  **Находка по ходу (16-13):** `RawXmlFragment` проверяет лишь, что строка — элемент, но не символы XML 1.0;
  фрагмент с управляющим символом из YAML репозитория дошёл бы до выгрузки нечитаемым файлом — задача 9.
- **Задача 4.** 45 тестов на 11 операций (пять новых классов `*IT`, два дополнены). Отказ роли не проверен
  у `GET /metamodel/elements` и `POST /ai/document`: обе операции доступны любой роли; у второй вместо роли —
  выключенный помощник (`403 ADVISOR_DISABLED`) и неизвестная модель без вызова API. `PUT …/label` без блокировки
  отвечает `200` — метка меняет историю, а не содержимое, и блокировки не требует. Расхождений с контрактом нет.
  Полная сборка с IT после задач 2–4: покрытие строк 94,1 % (было 92,5 %).
- **Задача 2.** Ни один тест на новых фейках не упал, и ни один обработчик не пишет в транзакции чтения.
  Две проверки отката до правки проходили и на старом фейке: в `ClientIdsScenariosTest` все отказы случались
  до первой записи, в `ImportRejectionTest` запись модели не проверялась. Добавлен отказ после записи связи
  (ребро с ключом, занятым узлом) и проверка, что модель не записана; на фейке без отката обе падают.
  Попутно: `GitFakes.MemoryOutbox` откатывал статусы записей очереди, но не новые записи.
- **Задача 9.** После проверки во фрагменте отказ кодирования в писателе стал недостижим: текст, атрибуты
  и фрагменты проверены при построении. Тест задачи 3, закреплявший поздний отказ писателя
  (`unencodableFragmentIsRejected`), заменён отказом при построении фрагмента.
- **Задача 7.** Слиты два самых больших контекста (`IntegrationTest` и `ApiTest` расходились одной
  `@AutoConfigureMockMvc`). Контексты помощника не слиты: предел частоты — свойство контекста, и тест предела
  (5 в минуту) с общим пределом 1000 потребовал бы тысячи запросов. База — `@ServiceConnection` через
  `@ImportTestcontainers`, адрес Keycloak по-прежнему `@DynamicPropertySource`: у него нет соединения Spring Boot.
  Пауза в `AdvisorSessionClaimIT` заменена ожиданием строки `pg_stat_activity` с `wait_event_type = 'Lock'`:
  тест теперь падает, если второе занятие не встало на блокировку, а не проходит на медленной машине.
- **Задача 6.** Разделял субагент в рабочей копии, переведённой на эту ветку; дифф прочитан, число утверждений
  по файлам сверено: убыло только там, где однотипные отказы свёрнуты в `@ParameterizedTest` (`AdvisorRequestTest`,
  `StyleOverrideTest`). Тестов стало больше на 77 (modeling-domain 252 → 290, advisor-domain 67 → 89,
  modeling-application 30 → 63, прочие — на единицы). Последовательности одного правила (`styleIsReplacedWhole`,
  `eventsFollowEveryUpwardTransition`) оставлены одним тестом.
- **Задача 5.** Статус до разбора тела механически проверяем — правило заведено в `TestSourceRulesTest`;
  на старом коде оно нашло 35 запросов MockMvc без проверки статуса, а не 9, как выборка ревью. Исключения
  правила: ответ отдан вызывающему (`return`, `ResultActions`) или статус читается из результата (`getStatus()`,
  асинхронный ответ). `LoadProfileIT` принимает ожидаемый `HttpStatus`, а не готовый `ResultMatcher`.
  **Ошибка, найденная по ходу:** `ObservabilityIT` искал `error_code="INV-MDL-006"` в любом месте выгрузки
  Prometheus; тег живёт на `modeling_usecase_errors_total`, а не на счётчике запросов, — проверка приращения
  по счётчику запросов упала бы. Число потерь картинки — ровно 2 (замена двух шрифтов), а не «не меньше 2».
  Часть в application-модулях (код и вид отказа, неизменность привязки, проверка сменённого потока) сделал
  субагент вместе с задачей 6.
- **Итог.** Чистая сборка `./mvnw -P '!frontend' clean verify` после последней задачи: 1069 юнит-тестов
  (было 780) и 178 интеграционных (было 133) зелёные, покрытие строк 94,1 % (было 92,5 %), проверки
  отказов домена и операций REST проходят.
