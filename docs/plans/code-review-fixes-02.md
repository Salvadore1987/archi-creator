# Исправления по этапу 2 ревью и приведение домена к стандарту

**Запрос от 2026-10-16:** исправить находки этапа 2 сразу; по D-18 и D-19 — решения владельца
ниже. Находки — [`docs/review/02-domen-modeling.md`](../review/02-domen-modeling.md).

## Решения владельца (2026-10-16)

- **D-18, `Optional`.** В полях `Optional` не хранится — поле держит само значение,
  отсутствие — `null`. Поле, которое не может быть пустым, проверяется в конструкторе
  (или в сеттере, где он есть). `Optional` — только внутри методов, где удобен.
  Параметры методов — тоже без `Optional`. Результат поиска (`find…` портов и выборок)
  остаётся `Optional`: этого требует стандарт (§2.7, ОБЯЗАТЕЛЬНО).
- **D-19, к стандарту.** Корни агрегатов — `AggregateRoot<Id>` (через `BaseEntity<Id>`,
  равенство по идентификатору), идентификаторы — `BaseId<UUID>`, события — `{Aggregate}{Action}Event`
  с базовым `{Aggregate}Event` на агрегат, корень исключений контекста — `{Context}DomainException`,
  агрегат создаётся фабрикой, а не публичным конструктором.
- **Охват — весь проект**: modeling, interchange, advisor. Этапы 3–4 ревью эти правила
  уже не найдут.

## Принятые уточнения (мои, по стандарту и устройству проекта)

- **Имена событий на проводе не меняются.** Тип в `outbox_event.event_type` и имена
  сообщений AsyncAPI — константы контракта (`JpaGitOutbox.EVENT_TYPE` = `"ModelVersionCommitted"`),
  они не выводятся из имени класса. Переименование класса в `…Event` не трогает ни контракт,
  ни данные в базе — миграция не нужна.
- **`BaseId.equals` сравнивает и класс.** В стандарте равенство по значению без учёта
  класса: `ElementId` и `FolderId` с одним UUID были бы равны. Это ослабило бы ту защиту
  типами, ради которой идентификаторы и типизированы.
- **Базовые типы — в каждом контексте свои** (`…<bc>.domain.common`): модули доменов
  друг от друга не зависят, общего ядра нет — как уже сделано с `DomainEvent`, `ArchiId`, `UuidV7`.
- **Lombok не вводится**: в проекте его нет; конструкторы и `equals` пишутся руками.
- **Без JSpecify.** Владелец выбрал проверку в конструкторе, а не разметку; D-14 остаётся
  открытым нарушением реестра.

## Расхождения плана с фактом

- **A2.** Доменный отказ при сборке графа дошёл бы клиенту `500`: `InvalidValueException`
  обработчики ошибок не знают, его переводит в `ModelingException.invalid` тот, кто строит
  доменное значение (контроллер — в `try`, как `bounds`/`style`). Граф обёрнут так же.
  Системный риск — любое необёрнутое построение доменного значения в контроллере даёт `500`;
  общего обработчика нет (см. заметку этапа 0 к этапу 11). Рекурсия `depthFirst` ограничена
  числом верхних узлов графа — отдельной правки не потребовала.
- **A3.** Мутаторы `TrackedMap` вызывали не только адаптеры хранения (`markPersisted`),
  но и тесты interchange (`DocumentMappingTest`) — вставляли узлы в представление напрямую.
  Тесты переведены на бизнес-методы `View` (`editNode`, `placeAnnotation`).
- **A7.** Опасение «встречный перенос папок одним запросом» не подтвердилось: у переноса
  одна цель, ранние шаги не меняют её предков — проверка по исходному дереву равносильна
  пошаговой, моделировать дерево не нужно.
- **A8.** Проверку литерала-аргумента в скрипте не завели: литерал доходил до `Message.of`
  через параметр метода, а латинских литералов вида `"BusinessActor"` в домене десятки,
  все законные — правило по тексту ловило бы шум, а не дефект. Сторож — тип параметра
  (`Message`, не `String`). Заодно переведены названия состояний модели (`ACTIVE` уходил
  в русский текст как есть). Тот же приём — `useCase` в отказе доступа interchange
  (`InterchangeOperation`) — к этапу 6 ревью.
- **A9.** Расширенная проверка нашла второе место, которое ревью пропустило:
  `interchange/domain/identity/package-info.java`.
- **A12, `textAlignment`.** Допустимость — `StyleOverride.validTextAlignment` (1, 2, 4), как
  у цвета; импорт кладёт в столбец только допустимое, незнакомое остаётся в остатке XML —
  round-trip не страдает. Риск: строка, записанная раньше через API с другим числом,
  при чтении из базы теперь откажет. Из Archi приходят только 1, 2, 4; если такая строка
  найдётся — миграция переносит значение в остаток.
- **B6a.** `InvalidValueException` перестал быть `IllegalArgumentException`: пять мест ловили
  IAE ради доменного значения (`ArchiTypeRegistry.findByXsiType` — на этом держится импорт
  незнакомой нотации, `ArchiId.of`, `ArchiType.of`, `AclEntry`, каталог метамодели помощника) —
  теперь ловят `InvalidValueException` явно. Обёртки в контроллере ради перевода отказа
  (`bounds`, `style`, граф разметки из A2) убраны: доменный отказ сам доходит до обработчика
  как `422 MDL_INVALID_INPUT`. Отдельные ветки `RelationNotPermittedException` в обработчике
  и `ErrorCodes` не нужны — перечень допустимых связей уходит в `details`.
- **Ошибка B6a, поймана при B6b.** Шестое место вне modeling — `MethodologyCheck.archiType`
  в interchange — тоже ловило IAE ради `ArchiType.of` и после B6a падало бы на файле
  с типом не в нотации ArchiMate (`canvas:…`). Тесты этого не покрывали, `verify` был зелёным.
  Исправлено с тестом `MethodologyCheckTest`. Урок: при смене иерархии исключения искать
  перехваты по всему реактору, а не по модулю, где класс объявлен.
- **B6b.** Корень interchange — без вида отказа (`Failure`): HTTP-статус для доменных отказов
  выбирает application-слой. Перехват в interchange по реактору проверен заранее: домен
  IAE/ISE ради своих исключений не ловил, `ImportService.request` переведён на явный
  `InvalidValueException`. К этапу 3 ревью: `ExportJob` на недопустимом переходе бросает
  голый `IllegalStateException` вне иерархии; `IllegalImportTransitionException` несёт
  команду латиницей (`"RejectImport"`) и состояние без перевода — тот же дефект, что 02-09.
- **B6c.** В advisor отдельный обработчик `InvalidValueException` стал не нужен — значение
  теперь `AdvisorDomainException`. `ResultReader` ловит его явно: нечитаемая находка модели ИИ
  по-прежнему пропускается. К этапу 4 ревью: `IllegalSessionTransitionException` передаёт
  в сообщение `from.name()` и имя перехода латиницей — тот же дефект, что 02-09.
- **B5.** Базовый тип событий агрегата — `sealed interface {Агрегат}Event extends DomainEvent`,
  а не абстрактный класс со ссылкой на агрегат, как в стандарте: события — record со снимком
  полей (уходят в outbox и после коммита), а record не наследует класс. Маркер `DomainEvent`
  без параметра типа: порты публикации принимают `Collection<DomainEvent>`, а `DomainEvent<T>`
  потребовал бы wildcard в параметре, который запрещает задача 5 этапа 1. `GitSnapshotCommittedEvent`
  создаёт сервис публикации, а не агрегат (смешанный способ из ADR-0023) — отнесён к агрегату
  привязки `GitBindingEvent`. Тип на проводе (`outbox_event.event_type`, AsyncAPI) не изменился.
- **B2.** `ArchiId` под `BaseId` не переводится: это значение-атрибут из файла Archi
  (столбец `archi_id`), а не ключ сущности; правило ArchUnit его исключает явно.
  `AggregateWrites` доставал UUID ключа отражением компонента record — теперь `BaseId.value()`;
  ключ сообщения об ошибке отражения удалён.
- **B4a.** Список корней правило берёт из раздела `aggregates:` в `spec/domain/<bc>/aggregates.yaml`:
  агрегат, объявленный в спецификации, без `AggregateRoot` в коде не останется. Составной ключ
  `IdempotencyRecord` — вложенный `record Key(scope, actor, key)`. У `ModelVersion` своё `equals`
  по идентификатору было и раньше (из-за массива снимка) — теперь это `BaseEntity`.
  Перевод record → класс сделан скриптом: тело компактного конструктора стало прологом перед
  `super(...)` (Java 25 это разрешает), обращения к полю `id` — `id()` по ошибкам компилятора.
- **Урок по ходу B4a.** Прогон модуля с `-pl` берёт соседние модули из локального репозитория
  Maven: после `verify` без `install` правило ArchUnit видело старый jar interchange и «падало»
  на уже исправленном коде. Перед `-pl` — `install`.

## Отменённые варианты

- **JSpecify `@Nullable` вместо `Optional`.** Предложен, владелец выбрал проверку в конструкторе.
- **Геттер, оборачивающий поле в `Optional`.** Требует превратить record в классы ради
  одного типа возврата; владелец решил поля не оборачивать.
- **Переименовать события и на проводе.** Сломало бы контракт AsyncAPI и открытые
  записи outbox ради имени класса.
