# Исправления по этапу 15 ревью — архитектурные проверки в сборке

**Основание:** находки [`docs/review/15-arkhitekturnye-proverki.md`](../review/15-arkhitekturnye-proverki.md);
порядок работы — как в планах этапов 1–14 (владелец 2026-10-22: «если есть изменения — сразу исправь»).

Каждая задача — проверка в сборке, прогон на старом коде (обязан упасть), перенос всех мест,
тесты затронутых модулей зелёные, один коммит. Код этапа почти везде уже соответствует правилу:
там, где нарушений нет, «прогон на старом коде» — порча правила или кода на время прогона.

## Порядок

Сначала решение о раскладке портов (1) — правило задачи 2 опирается на него. Затем правила ArchUnit (2–4, 7–9),
формат и PMD (5, 6). Порядок объявлений (10) — последним: перестановка трогает 31 файл, и остальные задачи
не должны с ней пересекаться.

## Расхождения плана с фактом

- **Задачи 2–4, 7, 8.** Код уже соответствовал правилам: нарушений не нашлось ни в домене, ни в портах,
  ни в контроллерах. «Прогон на старом коде» — порча на время прогона: из перечня домена убран генератор UUID,
  из допустимых типов порта — record, пакет сущностей заменён на `adapter.rest`, предел вызовов порта — ноль,
  во временный класс modeling положены строка `"archimate:Group"` и имя `ConcurrentModificationException`.
  Все правила падали.
  **Ошибка, найденная по ходу:** откат порчи через `mv` резервной копии возвращает файлу старое время
  изменения, и инкрементальная сборка Maven не пересобирает класс — следующий прогон видит испорченный код
  и падает, хотя исходник уже исправлен. Лечится `touch` после отката или `clean`; итог проверен чистой сборкой.
- **Задача 5.** `EmptyLineSeparator` (14 мест — лишняя пустая строка) не включён: §2.4 пустых строк не задаёт,
  а правило — вкус, а не ошибка. Ресурсы `try`, выровненные под открывающую скобку, переведены на продолжение +8:
  `Indentation` другого выравнивания не допускает.
- **Задача 6.** Все нарушения `CloseResource` — в тестах (`ExecutorService` и `HttpClient` закрывались
  `shutdownNow()` или не закрывались); в основном коде их нет — 03-18, 07-08 и 13-07 исправлены раньше.
  Исполнитель с `try-with-resources` ждёт свои задачи, а не прерывает их: в `AdvisorSessionClaimIT` защёлка
  отпускается во вложенном `finally` до закрытия, иначе при отказе утверждения тест ждал бы вечно.
- **Задача 9.** Фейк метрик стал методом экземпляра: датчик пишет, открыта ли транзакция фейка `UnitOfWork`.
- **Задача 10.** Перестановку сделал субагент; дифф проверен по коду: в каждом файле набор непустых строк
  совпадает с исходным. Нарушение «`private` раньше `public`» в `DiagramType` перестановкой не лечится —
  публичные константы создаёт конструктор, который читает приватный шаблон, и поставленный после них шаблон
  был бы `null`; шаблон вынесен во вложенный держатель. Заголовки разделов в `ModelRowsMapper` и `EntityMapper`
  поправлены: перегрузки двух направлений встали парами, и старые заголовки описывали не то.
- **Не заводились:** Error Prone ради `instanceof` с приведением (02-18), сверка полей агрегатов со спецификацией
  (04-10) — причины в файле находок.
- **Итог.** Чистая сборка `./mvnw -P '!frontend' clean verify -DskipITs` после последней задачи: 780 юнит-тестов
  зелёные, Checkstyle и PMD с новыми правилами — без нарушений; `check-comment-refs`, `check-string-literals`,
  `check-qualified-names`, `check-links`, `check-traceability` — чисто. Промежуточные коммиты по отдельности
  не собирались. Интеграционные тесты не прогонялись: три IT изменены только в закрытии ресурсов, их прогонит CI.
  Граф зависимостей перерисован — не изменился (зависимостей этап не трогал).
